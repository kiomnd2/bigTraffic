# Room 도메인 설계 보고서

**작성일**: 2026-02-23
**유형**: 도메인 설계 (신규)
**대상**: 사용자간 AccountBook 공유를 위한 방(Room) 기능

---

## 1. 배경 및 목적

현재 가계부(AccountBook)는 단일 사용자 소유 구조로, 복수 사용자(부부, 룸메이트, 동아리 등)가 하나의 가계부를 공동으로 관리할 수 없다. **Room(방)** 도메인을 도입하여 사용자간 가계부 공유 기능을 제공한다.

---

## 2. 설계 범위

| 포함 | 미포함 |
|------|--------|
| 방 생성/수정/해산 | 방장 위임 |
| 초대 코드 발급/참여 | 1회용 초대 코드 |
| 멤버 관리 (참여/탈퇴/추방) | 멤버 권한 세분화 (읽기/쓰기) |
| 방-가계부 연결/해제 | 기존 AccountBook 엔티티 수정 |

---

## 3. 엔티티 설계

### 3-1. Room (Aggregate Root)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | Long | PK |
| hostUserId | Long | 방장 userId |
| name | String(100) | 방 이름 |
| description | String(500) | 방 설명 |
| status | RoomStatus | ACTIVE / DISSOLVED |
| maxMemberCount | Integer | 최대 멤버 수 (기본 10) |
| createdAt | LocalDateTime | 생성 시각 |
| updatedAt | LocalDateTime | 수정 시각 |

### 3-2. RoomMember

| 필드 | 타입 | 설명 |
|------|------|------|
| id | Long | PK |
| roomId | Long | 소속 방 ID |
| userId | Long | 참여 사용자 ID |
| role | RoomRole | HOST / MEMBER |
| joinedAt | LocalDateTime | 참여 시각 |

- UNIQUE 제약: (roomId, userId)

### 3-3. RoomInvite

| 필드 | 타입 | 설명 |
|------|------|------|
| id | Long | PK |
| roomId | Long | 대상 방 ID |
| inviteCode | String(36) | UUID 기반 초대 코드 (UNIQUE) |
| status | InviteStatus | ACTIVE / EXPIRED / REVOKED |
| expiresAt | LocalDateTime | 만료 시각 |
| createdByUserId | Long | 생성자 userId |
| createdAt | LocalDateTime | 생성 시각 |

### 3-4. RoomAccountBook

| 필드 | 타입 | 설명 |
|------|------|------|
| id | Long | PK |
| roomId | Long | 방 ID |
| accountBookId | Long | 가계부 ID |
| linkedByUserId | Long | 연결 수행자 userId |
| linkedAt | LocalDateTime | 연결 시각 |

- UNIQUE 제약: (roomId, accountBookId)

## 10. 도메인 간 관계

```
Auth ──(userId)──> Room ──(accountBookId)──> AccountBook
```

- **Auth 도메인**: userId 값만 참조, User 엔티티 직접 참조 없음
- **AccountBook 도메인**: accountBookId 값만 참조, RoomAccountBook이 연결점 역할
- **기존 도메인 수정 없음**: AccountBook/Transaction에 roomId를 추가하지 않음

## 12. 핵심 설계 결정

1. **기존 도메인 수정 최소화**: RoomAccountBook 연결 테이블로 기존 AccountBook 안정성 유지
2. **N:N 초대 코드**: 여러 사용자가 같은 코드로 입장 가능. 1회용 필요 시 usedCount/maxUseCount 확장 가능
3. **방장 위임 미포함**: 이번 범위에서 제외. 필요 시 Room.hostUserId 변경 + RoomMember.role 교체로 확장
4. **Facade 패턴**: 도메인 간 조합(방 생성 + 방장 멤버십 생성 등)은 RoomFacade에서 트랜잭션 단위로 처리
